# Event assignment, recovery and sampled review implementation plan

**Goal.** Keep 260 annotators supplied with work, finish whole videos, and give five monitors a live queue of samples. Host Nightjar, PostgreSQL and the source frames on the organiser’s PC. Supervisely remains the annotation editor.

**Basis.** Local main at `c437894`, the [production benchmark](../../FULL_EVENT_BENCHMARK.md), and the event decisions in this chat. The benchmark used ten automated monitors inspecting all 30 frames. The event has five monitors inspecting samples. Retain both workloads for comparison.

## 2. Bound dashboard queries and preserve access rules

- [ ] In `labeling_api.py`, implement a shared cursor-paginated reader. Apply event, assigned-team, status and plan filters **before** ordering/limiting. Include a unique tie-breaker. Fetch bindings for page job IDs only; join or bulk-load both assignee and binding names. Preserve legacy response fields.
- [ ] In `reviews_api.py`, use this reader for assigned jobs. Replace per-image event scans with indexed membership and a monitor-team authorization join. Ensure historical jobs still authorize correctly. Enforce the same scope on annotation reads and review writes. Aggregate team/person counters in SQL in `review_dashboard_api.py`. In `reviews.tsx` and `review_dashboard.tsx`, page visible lists, refresh changed rows only and recover missed updates on reconnect.
- [ ] Seed a monitor’s jobs beyond the first 2,000 global records. Test returned IDs and denial for another monitor. Proposed acceptance budget: at most ten handler SQL statements independent of page size, and p95 under two seconds for normal pages with five concurrent monitors on the PC. Repeat the original ten-client, 2,000-row historical profile separately.

## 3. Establish frame identity and generate primary blocks

- [ ] Add an event import mode in `datasets_api.py` and the dataset UI that decodes every source frame exactly once in presentation order. Record immutable video ID, original checksum, extraction policy, integer frame ordinal, presentation timestamp/time base where available, dimensions, relative path and JPEG checksum. Keep MediaAsset ID as the canonical key. Thirty decoded frames span one second for verified 30 fps input; use recorded timestamps for variable-rate material.
- [ ] For supplied frame folders require unambiguous numeric ordering or a manifest. Surface gaps, collisions and unknown sampling density. Do not silently reinterpret a 1 fps dataset as full density. Reimport from its retained video into a new version when necessary. Keep existing movement/coverage frame ranges consistent. Estimate required disk from a representative full-density import before admitting the dataset.
- [ ] In a new `src/annotatiathon/work_queue.py`, implement pure `split_video(ordered_asset_ids, block_size=30)`. Keep contiguous primary frames from one video together, including a short final block. Persist a deterministic seeded draw of two distinct frame IDs per block at approval; for a one-frame tail select it once. Repreview/retry must preserve the draw.
- [ ] Test 1, 2, 29, 30, 31 and 900 frames, multiple videos, and distinct frame IDs with identical pixels. A 900-frame video yields **30 primary blocks, 60 second opinions, 960 annotations and 900 unique covered frames**. The 12-hour theoretical ceiling with this policy is 195 complete 900-frame videos before breaks, corrections and handoff delays.

## 4. Allocate from one shared queue

- [ ] Add typed contracts, additive migrations after `0015`, and model changes in `models.py`. Store plan version/seed, blocks, primary and duplicate frame requirements, attempts with person/team/epoch, per-frame confirmations, team checkout state and durable operations. Index due work by event/plan/state. Unique constraints enforce a single current owner per requirement and one open work packet per annotator. Backfill existing native mappings in bounded batches.
- [ ] Claim work in a short PostgreSQL transaction. Lock the team eligibility row and claim pending rows using SKIP LOCKED. Commit ownership and publish operation together. Keep one independent native job per annotator. Verified submission frees that person for a successor even when a sampled review is pending. Corrections remain linked to the original attempt. Preserve manual holds, launch/pause and event isolation.
- [ ] Prioritize interrupted blocks, then eligible blocks from videos closest to completion. Open another video when remaining unclaimed work cannot supply an idle eligible person. At closeout restrict new video starts using remaining time, observed pace and active capacity. Show distinct source frames confirmed, gaps, duplicate obligations and quality decisions separately. A video reaches primary completion only when every source frame is accounted for.
- [ ] Once the primary team is assigned, choose **one different eligible team at random for both repeat frames**, and persist the choice. Issue second opinions independently, blind to the first answer. Batch repeat obligations across blocks into packets of up to 30 images for one eligible assignee; dispatch short packets at closeout or when necessary to avoid idle time. Give repeats a fair share of dispatches. A checkout redraws only unfinished obligations; preserve completed contributions and prohibit reassignment to the primary team. Display outstanding duplicate coverage if no independent team is available.
- [ ] Reuse LabelingJob, NativeJobBinding and NativeMediaInstance for published attempts. Preserve separate native image identities even when remote content is deduplicated. Stage likely next blocks or reuse verified native bytes. The report measured 67.6 MB for one cold 30-image upload. Test simultaneous claims, repeated launch, pause, uncertain remote creation, duplicate independence and faster annotators receiving more blocks.

## 5. Manual team checkout and lossless recovery

- [ ] Add **Check out team** to team operations for organisers and the assigned monitor. Preview both members, open attempts, future reservations and recovery status. Use an idempotent event-scoped checkout endpoint. Keep check-in history, tickets, identities and historical ownership intact. Use this explicit action as the departure signal.
- [ ] Atomically disable new claims for both people, revoke claim epochs, return never-published reservations and enqueue recovery for in-flight work. A publication finishing after checkout must record its native IDs against the old attempt and enter recovery. Retain submitted work and open quality reviews.
- [ ] For a live assignment, capture current saved work, fence further native edits using the rehearsed stop procedure, then reconcile final per-image states. Atomically persist the source/native IDs, confirmation state, partial JSON, digest, author, round and capture time. Keep old native jobs and copies. Seed a replacement copy from a partial answer only if the SDK transfer has been verified and provenance is preserved.
- [ ] Requeue only unfinished obligations after durable capture and fencing. For 18 confirmed out of 30, retain those 18 and recover exactly 12; any partial edits among the 12 remain traceable. If the remote service is down or confirmation is ambiguous, show **Needs reconciliation** and retain exclusive ownership until resolved. Test duplicate clicks, PC restart at each boundary, checkout during upload, stale workers, late edits, mixed states for two teammates, and another monitor’s access denial.

## 6. Decouple publishing, status, review fetches and export

- [ ] Refactor `native_worker.py` and `native_operations_api.py` so publishing drains available operations independently from metadata polling, corrections, capture and export. Select indexed due records instead of scanning all jobs and completed manifests every pass. Use bounded concurrency, a DB session per worker, leases/fencing and a shared external request budget. Keep network calls outside database row locks. After uncertain creates, reconcile deterministic remote names and IDs before retrying. Back off on throttling; surface permission errors. Coordinate all lanes with pause, archive and the existing native reset operation.
- [ ] In `native_export_api.py` batch local mapping/score reads and group remote annotation reads by dataset. Checkpoint by source ID, native image ID, attempt and round. Reuse cached JSON only when its revision is verified against the export policy. Preserve primary, duplicate, partial, corrected and adjudicated answers with provenance. Validate per-ID completeness and ZIP checksums before declaring success. Interrupt/restart must resume without double entries. The report exported 8,250 copies in 496 seconds; measure a full-volume closeout before budgeting event-day export time.
- [ ] Instrument publish wait, time to next available job, queue age, metadata freshness, SDK requests/bytes, throttling, retry counts and export throughput. Exercise the 260-job burst, cold uploads, higher network latency and restart immediately after a remote success.

## 7. Deliver a sampled review queue with on-demand overlays

- [ ] Persist one routine monitor sample per primary block. Select the participant’s first confirmed image for onboarding, then one uniformly selected frame per subsequent block. If checkout makes the selected frame unreachable, sample a confirmed frame from that partial block if available. Record selection reason, reviewer claim and annotation revision. Distinguish routine samples, repeat disagreements, targeted follow-ups and correction checks. Repeated polling must not enqueue the same sample twice.
- [ ] Feed each monitor a metadata-only list of ready names with video/ordinal, participant/team, reason, current state and reviewer. Refresh as confirmations arrive through shared server-side polling. Show freshness and a submission-based fallback when early confirmation is unavailable. Clicking a row claims the review and retrieves only its original image and annotation JSON; dashboard arrival or refresh must not trigger geometry downloads. Closeout and interrupted-job recovery are explicit bulk capture operations.
- [ ] Resolve native image → NativeMediaInstance → MediaAsset → dataset root/media/relative path. Check authorization, hash and dimensions before using `AnnotationFrame`. Store the exact reviewed JSON and digest per attempt/round. Reuse immutable originals with authenticated cache revalidation, and invalidate current annotation previews after edits. Test duplicate basenames, identical images at different ordinals, independent copies, zoom/resize, switched users, stale revisions and missing local files.
- [ ] Extend existing review scoring with append-only decisions, flags by error category and bird/landmark, reviewer, capture time and correction disposition. Validate required box and visible/occluded landmark classes per bird using the event rubric. Define a confirmed-empty policy with the organiser. An incomplete confirmed answer should reach the error workflow. Compare independent repeats by matching the same bird and landmark, preserve both answers, and route material disagreement to adjudication. Two differing labels alone cannot establish which annotator made an error.
- [ ] Extend `reviews_api.py`, `review_dashboard_api.py`, `reviews.tsx` and `review_dashboard.tsx` with confirmed frames, distinct reviews, flagged images, individual mistakes, verified corrections and sample denominators per person and team. One image with three mistakes contributes one flagged image and three errors. A repeat inspection must not inflate the original count. Report targeted follow-ups separately when interpreting quality rates. With five monitors, one sample per 30 primary frames gives roughly 35 seconds per inspection at the original peak before breaks and follow-ups; record actual backlog and review time.

Record burst drain time and degraded-network results separately. Require zero lost evidence, duplicate active owners, unauthorized reads, or false complete videos. Verify browser overlays and review ergonomics with real monitors.
- [ ] Use `compose.live.yaml` as the starting point for local PostgreSQL, API, worker and web. Use persistent SSD storage outside OneDrive, stable encryption key, an HTTPS hostname/gateway to loopback Nginx, and outbound access to Supervisely. Test from all five monitor devices on venue Wi-Fi. Account for raw videos, full-density JPEGs, staging, JSON, exports and off-host backups. At the benchmark’s illustrative 2.25 MB per JPEG, 175,500 unique frames alone require about **395 GB**. Measure the real files. Four vCPUs and 8 GiB are a provisional stack budget; reserve capacity for the PC’s OS.
- [ ] Back up and restore PostgreSQL, matching key and media on a clean disk/host; verify frame IDs, review history and dispatch recovery. Rehearse power loss, disk-full handling and loss of the external connection. Run the repository test suite, frontend build, PostgreSQL concurrency tests, real-instance rehearsal and sustained soak. Enable the new queue mode first on a fresh rehearsal event. Keep the old plan mode available for existing data.

**Implementation sequence.** Start with the SDK rehearsal and read-path fix. Frame identity unlocks the queue and checkout. Implement independent publishing against the new claim/recovery contract, then enable sample review and rebenchmark the workflows together.
